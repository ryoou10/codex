1. Codexとは

一言でいうと：
Codexは、コードを書く・読む・直す・レビューする・出荷する作業を支援するOpenAIのAIコーディングエージェントです。

OpenAI公式ページでは、Codexはエンジニアリング作業を加速するAIコーディングパートナーとして説明されています。 機能開発、リファクタリング、レビュー、リリースなど、実際の開発作業を支援することを目的としています。

OpenAI Developers公式ドキュメントでは、Codexはソフトウェア開発向けのコーディングエージェントであり、コードを書く、質問に答える、テストを実行する、変更を提案する、Pull Requestを作るといった作業に使えると説明されています。

2. Codexでできること

Codexは単なるコード補完ツールではなく、開発作業全体を支援するエージェントです。 公式情報をもとに整理すると、主な使い方は以下の通りです。

コードを書く

新しい機能の実装、既存コードの修正、HTML/CSS/JavaScriptなどの作成を支援します。

コードを読む

既存のプロジェクトや知らないコードの構造を理解する手助けをします。

バグを直す

エラー原因の調査、修正案の提示、必要に応じたコード変更を支援します。

テストを実行する

ローカル環境やクラウド環境で、テストや検証を行う作業を支援します。

レビューする

変更内容を確認し、問題や改善点を見つける作業を支援します。

出荷を助ける

Pull Request、リリース、移行作業など、開発成果を届けるまでの工程を支援します。

3. Codexを使える場所

Codexは、複数の場所から利用できます。作業内容や使いやすさに応じて、CLI、IDE拡張、Codex Web、Codexアプリなどを使い分けます。

利用形態 概要 向いている作業
Codex CLI ターミナルからローカルでCodexを使う方法です。選択したディレクトリ内のコードを読み、変更し、実行できます。 ローカル開発、ターミナル操作、コード修正、検証
Codex IDE extension VS Code、Cursor、WindsurfなどのIDE内でCodexを使う方法です。 エディタ横での相談、ファイル編集、コード理解
Codex Web / Cloud クラウド環境でCodexに作業を任せる方法です。バックグラウンドや並列タスクに使えます。 複数タスク、時間のかかる作業、GitHub連携
Codex App macOSやWindowsで使えるアプリ版です。プロジェクト横断の作業やレビューに向いています。 ローカル作業、プロジェクト管理、変更確認

4. 基本の使い方

初心者は、いきなり大きな変更を任せるより、小さな対象ファイルと明確な目的を指定するのが安全です。

1. 対象を指定
2. 目的を伝える
3. 制約を伝える
4. 変更を確認
5. テスト・公開
初心者向けの指示例：
対象は index.html のみです。スマホ表示を読みやすくしてください。本文の意味は変えず、CSS中心に改善してください。

Codexに依頼するときは、「何を」「どこまで」「何を変えないか」を明確にすると、意図しない変更を減らせます。

5. プランモード的な使い方

Codexの公式ベストプラクティスでは、複雑・曖昧・説明しづらい作業では、先に計画を立てさせる使い方が有効とされています。 実装前に方針を確認することで、意図しない変更や手戻りを減らしやすくなります。

考え方：
いきなりコードを書かせるのではなく、まず「どこをどう直すか」を説明させてから実行します。

使い分け

作業内容 おすすめ 理由
誤字修正 通常の依頼 範囲が狭いため、計画は不要なことが多いです。
HTML全体の改善 先に計画 構成・CSS・スマホ表示など複数要素が絡むためです。
複数ファイルの修正 先に計画 影響範囲を確認してから作業した方が安全です。
公開前チェック 先に計画 個人情報、公開リスク、表示崩れを確認しやすくなります。

6. 対応プランと使用量

OpenAI Help Centerでは、Codexは対象のChatGPTプランに含まれると案内されています。 使用量の扱いはプランやタスクの大きさ、複雑さ、利用形態によって変わります。

注意：
Codexの使用量やレート制限は変更される可能性があります。最新の対象プラン、使用上限、クレジット情報は必ずOpenAI公式ヘルプと料金ページで確認してください。

公式ヘルプでは、Codexの使用量はタスクの大きさ、複雑さ、実行場所などによって変わると説明されています。 そのため、「1回の依頼で必ず何％消費する」といった固定の考え方ではありません。

7. ログイン方法

OpenAI Developers公式ドキュメントでは、CodexでOpenAIモデルを使うログイン方法として、ChatGPTアカウントでのサインインとAPIキーでのサインインが説明されています。

ログイン方法 概要 補足
ChatGPTでサインイン ChatGPTプランの利用権限を使ってCodexにアクセスします。 Codex CloudではChatGPTでのサインインが必要とされています。
APIキーでサインイン API利用に基づく方法です。 CLIやIDE拡張では、複数のサインイン方法がサポートされています。

8. 安全面の注意

Codexはコードやファイルを読んだり、変更したり、実行したりできるため、便利な反面、扱う情報には注意が必要です。

公開・共有前に確認すること：
  • APIキー、トークン、パスワードを含めない
  • 個人情報を含めない
  • 社内情報や業務手順をPublicリポジトリに置かない
  • Codexに触らせる対象ファイルを必要最小限にする
  • 実行前・反映前に変更内容を確認する

公式ドキュメントでは、設定、認証、管理者コントロール、データ取り扱いの違いなどが案内されています。 仕事や社内情報を扱う場合は、所属組織のルールを優先してください。

9. 公式推奨の使い方

OpenAI DevelopersのCodexベストプラクティスでは、Codexを効果的に使うための考え方として、明確な指示、計画、検証、設定、スキル、MCPなどが扱われています。

範囲を絞る

対象ファイルや作業範囲を明確にします。

目的を明確にする

何を達成したいのかを先に伝えます。

変更前に計画させる

複雑な作業では、先に方針を出させます。

検証する

変更後に表示確認やテストを行います。

秘密情報を守る

APIキーや社内情報を公開しないようにします。

GitHubと組み合わせる

Issue、Branch、Pull Request、Pagesなどと組み合わせると管理しやすくなります。

10. 初心者向けおすすめ運用

HTML作成やGitHub Pages公開を中心に使う場合は、いきなり大きな自動化を狙うより、次の流れが安全です。

HTML作成
GitHub保存
Codexで確認
小さく修正
Pages公開
おすすめプロンプト：
対象は index.html のみです。本文の意味は変えず、スマホ表示とCSSだけ改善してください。まず変更方針を提示し、まだ編集しないでください。

社内マニュアルや業務手順を扱うHTMLは、PublicではなくPrivateリポジトリで管理するのが安全です。 公開用には、個人情報・社内情報・業務上の設定値を削ったサンプル版を作る方が適しています。
