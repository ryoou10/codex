# TSUMUGI(紡)— Cross-Modal Consistency Orchestrator

複数の生成AI(言語・コード・音楽・映像・ビジュアル)の出力を、**1つの作品として整合させる**ためのオーケストレーションツール。

## なぜ既存のAIツールでは補えないのか

| ツール | 得意領域 | できないこと |
|---|---|---|
| Claude | 長文推論・脚本・コーディング | 音楽や映像そのものの生成 |
| ChatGPT Codex | 自律的なコード生成 | コード以外のモダリティ |
| Hermes agent | エージェント的なタスク実行 | クリエイティブ生成の品質判定基準を持たない |
| Seedance 2.0 | 動画生成 | 自分の映像が「曲のBPMと合っているか」を知らない |
| TapNow | ビジュアル生成 | 自分のパレットが「作品全体の感情設計と合っているか」を知らない |
| Suno | 楽曲生成 | 自分の曲が「映像のカット割りと同期するか」を知らない |

上記はすべて**単一モダリティの生成器**です。複数のAIで1つの作品を作ろうとすると、各AIはプロンプトを独立に解釈するため、**曲のテンポと映像のカットがズレる・感情の起伏が揃わない・色調と曲調がチグハグ**という問題が必ず起きます。そして、このズレを**定量的に検出し、ズレた箇所だけに修正指示を出して再生成させる**機能は、上記のどのツールにも存在しません。

TSUMUGI はその「あいだ」を埋める統合層です。生成は一切自前で行わず(=既存ツールと競合せず)、**指揮**だけを行います。

## 中核となる3つの仕組み

### 1. クリエイティブ・ブループリント(単一の作品仕様)
作品を「感情の時間軸」として定義します。各ビート(起承転結など)は正規化時刻 `at` と感情ベクトル `mood`(valence=陰陽 / arousal=静動 / tension=緊張)を持ち、**全モダリティへの指示書はここから導出**されます。ビート間の感情は線形補間され、任意の時刻の「目標感情」が定義されます。

### 2. ハーモニー・エンジン(クロスモーダル整合性検証)
各AIの出力マニフェストをブループリントと相互に突き合わせ、採点します。

- **duration** — 音楽・映像の尺がブループリントと一致するか(許容誤差 2%)
- **tempo_sync** — 楽曲BPM ÷ 映像のカットレートが「1小節(4拍)の倍数」に乗るか。乗っていればカットが小節境界に落ち、音楽的に同期する
- **emotion** — 音楽・映像が報告する感情曲線と目標感情曲線のコサイン類似度(閾値 0.95)
- **palette** — キービジュアルの暖色比率が作品全体の valence と整合するか

不合格の項目には、**該当アダプタ宛ての修正指示(directive)**が生成され、次回の再生成にそのまま渡されます。「生成 → 検証 → 修正指示 → 再生成」のループが収束するまで自動で回ります。

### 3. 来歴台帳(Provenance Ledger)
すべての成果物について「どのAIサービスが・どのリビジョンで・いつ生成したか」を**ハッシュチェーン式の追記専用台帳**(`ledger.jsonl`)に記録します。後からの改竄・差し替えは `verify` で検出されます。公開前の権利確認(各サービスの利用規約・商用利用条件・AI生成物の表示義務)の根拠資料になります。法令・規約順守を**ワークフローの構造として**組み込んでいるのが特徴です。

## パイプライン

```
script(Claude)─┬─ music(Suno)──────┬─ player(ChatGPT Codex)── release(Hermes agent)
               ├─ video(Seedance 2.0)┤
               └─ keyvisual(TapNow)──┘
```

- **script** — ブループリントから脚本・シーン記述を生成
- **music / video / keyvisual** — 各モダリティの生成
- **player** — 音と映像をキューポイントで同期再生する HTML プレイヤーのコード生成
- **release** — 公開前チェックリストと権利確認項目の生成(全上流成果物を対象)

## かんたん起動(ダブルクリック)

必要なのは Python 3.10 以上だけです(https://www.python.org/downloads/ から入手。
Windows はインストール時に「Add Python to PATH」に必ずチェック)。

1. このリポジトリを ZIP でダウンロードして展開する
2. `2026-06-10/tsumugi` フォルダを開く
3. Windows は `起動_Windows.bat`、Mac は `起動_Mac.command` をダブルクリック
4. ブラウザが自動で開く(開かない場合は http://127.0.0.1:8765/ を手動で開く)

※ Mac で「開発元が未確認」と出る場合は、ファイルを右クリック →「開く」を選択。
※ 黒いウィンドウ(ターミナル)はサーバー本体です。使用中は閉じないでください。

## 使い方(Webアプリ)

依存ライブラリなし(Python 3.10+ 標準ライブラリのみ)で起動できるローカルアプリを同梱しています。

```bash
python3 -m tsumugi.app --port 8765 --workspace ./tsumugi-workspace
# → http://127.0.0.1:8765/ をブラウザで開く
```

- **ブループリント** — 感情曲線(valence/arousal/tension)をスライダーで編集し、SVGグラフでリアルタイム確認。ビートの追加・削除も可能
- **整合性** — 生成(weave)/ 検証(check)/ 修正再生成(revise)/ 自動収束(auto)をボタン操作で実行し、スコアと修正指示を表示
- **成果物** — 各AI役のマニフェストと同期プレイヤー(player.html)を閲覧
- **来歴台帳** — 全生成記録の閲覧とハッシュチェーン検証

サーバーは既定で `127.0.0.1` にのみバインドします(ローカル専用)。プロジェクト名の検証とパス封じ込めにより、ワークスペース外のファイルには触れません。

## 使い方(CLI)

```bash
# 1. プロジェクト作成(blueprint.json が生成されるので感情設計を編集)
python3 -m tsumugi.cli new myproject --title "黎明" --theme "夜明けの街と一杯の珈琲" --duration 60

# 2. 全ステージ生成
python3 -m tsumugi.cli weave myproject

# 3. 整合性チェック(不整合なら修正指示が出る)
python3 -m tsumugi.cli check myproject

# 4. 修正指示を適用して再生成
python3 -m tsumugi.cli weave myproject --revise

# または、収束するまで自動で回す
python3 -m tsumugi.cli auto myproject

# 来歴台帳の検証
python3 -m tsumugi.cli verify myproject
```

実行例(初回は不整合が検出され、修正ループ1回で収束):

```
総合スコア: 0.9235 [FAIL]
  [x] tempo_sync       0.7599  BPM 98.0 / 16.12 cuts/min = 6.08 拍/カット
      -> 修正指示 (video): 1カット 6.08拍は小節境界(8拍)から 24.0% ズレている
  [x] emotion:music    0.9306  music の感情曲線一致度 0.931(閾値 0.95)
...(--revise 後)...
総合スコア: 0.9862 [PASS]
  [o] tempo_sync       1.0000  BPM 98.0 / 12.25 cuts/min = 8.00 拍/カット
来歴台帳: PASS (14 entries verified)
```

## シミュレーションモードと実接続

- 対応する環境変数(`ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `SUNO_API_KEY` / `SEEDANCE_API_KEY` / `TAPNOW_API_KEY` / `HERMES_API_KEY`)が**未設定の場合は常にオフラインのシミュレーションモード**で動作します。各アダプタはブループリントから決定論的にマニフェストを導出し、意図的に「独立したAIの解釈ズレ」を含むため、整合エンジンと修正ループの全動作を実機なしで検証できます。
- 実サービスへの接続は各アダプタの `generate_live()`(`tsumugi/adapters/builtin.py`)に各社の**公式API**クライアントを実装してください。本リポジトリでは未実装であり、呼び出すと明示的なエラーになります。非公式な手段でのアクセスは行わない設計です。

## 法令・規約への配慮

- 生成そのものは各サービスの公式APIに委ねる前提であり、スクレイピング等の規約違反手段は使いません
- 来歴台帳により、成果物ごとの生成元・生成日時が常に立証可能です
- release ステージ(Hermes agent)が、公開前に各サービスの利用規約・商用利用条件・AI生成物表示義務の確認を成果物単位で要求します
